# Журнал змін контракту

Власник файлу: серверний розробник. Правила версій — у `WORKFLOW.md`, розділ 4.

Кожен запис каже, що змінилось, чи ламає це сумісність і яких спек стосується. Відповіді на запити мобільного розробника (`requests/CR-…`) теж записуються тут.

## 0.1.0 — 2026-11-10

Перша версія контракту для MVP. Ще не позначена тегом: тег `v0.1.0` ставить серверний розробник після того, як обидва розробники переглянуть контракт.

### Додано

| Контракт | Зміст | Функції та інше |
|---|---|---|
| `001-conventions` | Загальні правила: виклик функцій, формат відповіді, типи, місто, гість, списки, помилки, кеш, посилання всередині додатку | `get_app_config` |
| `002-home-layout` | Макет головної з даними віджетів | `get_home` |
| `010-alerts` | Стан тривоги, чотири рівні, правила свіжості | `get_alert_state`, канал `alerts:<city_id>` |
| `011-power` | Графік відключень за чергами | `get_power` |
| `020-catalog` | Розділи, категорії, фільтри | `get_catalog` |
| `021-events` | Події, сеанси, стрічки головної | `list_events`, `list_event_points`, `get_events_feed`, `get_event` |
| `022-places` | Місця й сервіси | `list_places`, `list_place_points`, `get_place` |
| `030-map` | Вигляд карти й шари | `get_map_config`, `get_map_layer` |
| `031-offline` | Офлайн-список і офлайн-карта | `get_offline_manifest`, файл списку, файл карти |
| `040-push` | Сповіщення про тривогу | `register_device`, `unregister_device`, вміст сповіщення |
| `060-reports` | Повідомлення про проблему | `submit_report` |
| `080-analytics` | Події аналітики | `track_events` |

Разом 19 функцій, один канал реального часу, два формати файлів.

### Рішення, закладені в цю версію

- Додаток звертається до сервера лише через серверні функції бази; один екран — один запит.
- Гість розпізнається за ідентифікатором встановлення.
- До кожної відповіді є схема JSON і приклади; відповідність перевіряє `tools/check-fixtures.mjs`.
- Сповіщення в MVP лише про тривогу.
- Повідомлення каналу тривоги — лише сигнал: додаток підтверджує його запитом `get_alert_state` (`010`, правило 5 для додатку). Причина: у відкритий канал може писати не лише сервер. Додано 10.11.2026 під час написання спеки `110-alerts`, до встановлення тегу.

### Відкриті питання цієї версії

Зібрано в розділах «На що звернути увагу» кожного контракту. Найважливіші:

1. Чи дає API «Повітряна тривога» тип «розвідувальний БпЛА» (`010`).
2. Як сервер повертає потрібні коди HTTP для помилок (`001`).
3. Формат файлу офлайн-карти потребує практичної перевірки (`031`).
4. Постачальник тайлів карти не обраний (`030`).
5. Чи може гість читати закритий канал реального часу, у який пише лише сервер (`010`; дослідження R1 спеки `110-alerts`).
