# 083 — Лейбли постійного клієнта (labels)

Діє з версії контракту `0.5.0`. Власник: серверний розробник.
Парні спеки: `183-customer-labels` (сервер), `283-my-labels` (додаток).
Схема: `schemas/083-labels.schema.json`. Приклади: `fixtures/083-labels/`.

## Призначення

Заклад чи фемілі має один лейбл постійного клієнта: назву («Постійний клієнт», «VIP») і бенефіт (наприклад «знижка 10%») задає власник. Він видає лейбл за власними фільтрами або вручну й так само знімає (`PLAN.md`, рішення 66). Додаток показує учаснику його лейбли; знижку працівник застосовує сам на касі після сканування QR, додаток нічого не рахує.

Видача й зняття лейблів, фільтри й аналітика власника — це кабінет партнера на сервері; у цьому контракті їх немає.

## Функція `list_my_labels`

Потрібен вхід і участь у програмі. **Параметри:** немає.

**Відповідь** (`$defs/list_my_labels`): `items[]`.

| Поле | Опис |
|---|---|
| `owner.kind` | `place` або `family` |
| `owner.id`, `owner.title` | Заклад чи фемілі, що видали лейбл |
| `place_ids[]` | Заклади, де лейбл діє: один для закладу, усі заклади фемілі для фемілі |
| `title` | Назва лейбла, задана власником |
| `benefit` | Текст бенефіту, заданий власником; до 120 символів |
| `conditions` | Умови отримання лейбла текстом, лише якщо заклад (фемілі) увімкнув їх показ для свого лейбла; за замовчуванням `null` |
| `granted_at` | Коли видано |

**Помилки:** `unauthenticated`; `forbidden` — користувач не учасник програми.

## Сповіщення

До типів `054-notification-prefs` додається ключ `label_granted` (увімкнено): «Ви стали постійним клієнтом у закладі X». Про зняття лейбла сповіщення немає. Вміст — `push_message_loyalty` з `081-loyalty` з `data.type = "label_granted"` (при встановленні тегу значення додається в перелік схеми `081`).

## Правила для сервера

1. Умови отримання віддаються в `conditions`, лише якщо власник увімкнув їх показ для цього лейбла (рішення 90 у `PLAN.md`); за замовчуванням показ вимкнено й `conditions` дорівнює `null`. Самі налаштування фільтрів користувачу не віддаються ніколи: `conditions` — текст, який власник показує свідомо.
2. Текст `benefit` проходить перевірку на заборонені обіцянки (гроші, алкоголь безкоштовно) під час збереження власником.
3. Знятий лейбл зникає з відповіді одразу.
4. Лейбл, виданий власником вручну, фільтр зняття не знімає; зняти його може лише власник вручну.

## Правила для додатку

1. Перелік зберігається в кеші акаунта. На сторінці місця додаток показує лейбл, якщо ідентифікатор місця є в `place_ids` якогось елемента; відповідь `get_place` для гостя й учасника однакова.
2. Текст бенефіту показується як є, з приміткою «Умови визначає заклад». Якщо `conditions` не `null`, умови показуються під бенефітом як є.
3. Додаток не обчислює знижок і не показує, скільки лишилось до лейбла.
4. Після виходу з акаунта лейблів на пристрої немає.
