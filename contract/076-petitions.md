# 076 — Петиції (petitions)

Діє з версії контракту `0.4.0`. Власник: серверний розробник.
Парні спеки: `176-petitions` (сервер), `276-petitions` (додаток).
Схема: `schemas/076-petitions.schema.json`. Приклади: `fixtures/076-petitions/`.

## Призначення

Перелік петицій з офіційного порталу міської ради: назва, стан, кількість підписів. Підписати петицію можна лише на офіційному сайті; додаток туди веде (рішення 76 у `PLAN.md`: оригінал відкривається в системній вкладці браузера, текст у додаток не копіюється).

## Функція `list_petitions`

| Параметр | Тип | Обов'язковий | Опис |
|---|---|---|---|
| `p_city_id` | UUID | так | Місто |
| `p_status` | код | ні | Один зі станів нижче; без параметра — усі, спершу ті, що збирають підписи |
| `p_limit`, `p_cursor` | | ні | Див. `001-conventions`, розділ 6 |

**Відповідь** (`$defs/list_petitions`): `items[]`, `next_cursor`, `source` (назва й адреса порталу), `synced_at` (коли сервер востаннє звірявся з порталом).

**Картка петиції** (`$defs/petition_card`)

| Поле | Опис |
|---|---|
| `id` | Ідентифікатор у додатку |
| `number` | Номер петиції на порталі або `null` |
| `title` | Назва |
| `status` | `collecting` (збір підписів), `under_review` (на розгляді), `answered` (є відповідь), `not_supported` (не набрала підписів) |
| `status_title` | Готовий підпис стану |
| `signatures`, `signatures_goal` | Зібрано й потрібно; `signatures_goal` може бути `null` |
| `ends_at` | Дата міста, до якої триває збір підписів, або `null` |
| `published_at` | Дата публікації на порталі |
| `url` | Сторінка петиції на порталі |

## Правила для сервера

1. Джерело одне — офіційний портал; петиції вручну не створюються.
2. `synced_at` показує справжній час останньої вдалої звірки; якщо портал недоступний, дані лишаються старі, а час не оновлюється.
3. Невідомий стан порталу сервер зводить до найближчого з чотирьох і віддає власний `status_title`.

## Правила для додатку

1. Дотик до картки й кнопка «Підписати на офіційному сайті» відкривають `url` у системній вкладці браузера (Chrome Custom Tabs на Android, `SFSafariViewController` на iOS), ніколи не у WebView: у WebView постачальники входу для підпису блокуються. Для новин, петицій і зборів у додатку один спільний помічник відкриття (рішення 76 у `PLAN.md`).
2. Додаток не збирає підписів і не просить даних для них.
3. Поруч зі списком завжди видно джерело й час звірки (`synced_at`).
4. Прогрес підписів показується, якщо є `signatures_goal`.
5. Невідоме значення `status` показується з `status_title` без особливого оформлення.

## Оновлення

Під час відкриття розділу, не частіше ніж раз на 30 хвилин; оновлення жестом.

## Приклади

- `list_petitions.default.json` — три петиції в різних станах.
- `list_petitions.empty.json`.

Тексти петицій у прикладах вигадані.

## На що звернути увагу

- **Спосіб отримання даних** (відкритий інтерфейс порталу чи розбір сторінок) — питання спеки `176-petitions`; контракт від нього не залежить.
- **Кількість підписів може відставати** від порталу; тому час звірки обов'язковий на екрані.
