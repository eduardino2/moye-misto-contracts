# 001 — Загальні правила (conventions)

Діє з версії контракту `0.1.0`. Власник: серверний розробник.
Парні спеки: `101-foundation` (сервер), `201-app-shell` і `250-profile-guest` (додаток).
Схема: `schemas/001-conventions.schema.json`, спільні типи: `schemas/common.schema.json`. Приклади: `fixtures/001-conventions/`.

Цей файл описує правила, спільні для всіх інших контрактів. Якщо інший контракт про щось мовчить, діє написане тут.

## 1. Як додаток звертається до сервера

1. **Усі запити — це серверні функції бази (RPC).** Додаток викликає їх через клієнт Supabase: `supabase.rpc('<назва>', params: {...})`, що відповідає `POST /rest/v1/rpc/<назва>`. Напряму таблиці додаток не читає і не пише.
2. **Один екран — один запит.** Функція повертає все, що потрібно екрану для першого показу, одним об'єктом JSON. Головна отримує макет разом із даними віджетів (`002`), сторінка події — картку разом із сеансами (`021`).
3. **Миттєві зміни — канал реального часу.** У MVP ним користується лише тривога (`010`). Усе інше оновлюється повторним запитом.
4. **Ключ доступу.** Додаток використовує тільки публічний ключ Supabase. Жодних інших ключів у додатку немає.
5. **Назви функцій:** `get_…` (один об'єкт), `list_…` (список), `register_…`, `submit_…`, `track_…` (запис). Усі параметри мають префікс `p_`. Необов'язковий параметр можна не передавати або передати `null`.

## 2. Формат відповіді

1. Функція завжди повертає один об'єкт JSON, навіть для списку.
2. **Усі поля, описані в схемі, присутні завжди.** Якщо значення немає, поле дорівнює `null` (або порожньому масиву), а не пропускається.
3. Кожна відповідь на читання має поле `generated_at`: момент, коли сервер зібрав відповідь.
4. Тексти для користувача сервер віддає українською, звичайним текстом без розмітки. Перенесення рядка дозволено лише в полях `description`.

### Сумісність уперед

Ці три правила дозволяють серверу розвиватись без оновлення додатку, тому вони обов'язкові для додатку:

- невідоме поле у відповіді додаток ігнорує;
- невідоме значення переліку (тип віджета, тип фільтра, позначка, тип контакту) додаток пропускає без помилки: такий елемент просто не показується;
- невідоме посилання `moyemisto://…` не відкривається, а елемент із ним ховається.

Схеми суворі (`additionalProperties: false`): вони перевіряють сервер на конкретній версії контракту. Суворість схеми не дає додатку права падати на новому полі.

## 3. Типи даних

| Тип | Формат | Приклад |
|---|---|---|
| Ідентифікатор | UUID, малі літери | `7c1f0c5e-6a54-4c0f-9a59-1d6f3a2b0001` |
| Момент часу | ISO 8601 у UTC, суфікс `Z` або `+00:00` | `2026-11-10T09:00:00Z` |
| Дата міста | `РРРР-ММ-ДД` у часовому поясі міста | `2026-11-10` |
| Час доби | `ГГ:ХВ` у часовому поясі міста; `24:00` лише як кінець проміжку | `18:00` |
| Координати | об'єкт `{ "lat": …, "lng": … }`, WGS 84 | `{ "lat": 51.4982, "lng": 31.2893 }` |
| Відстань | цілі метри, поля з суфіксом `_m` | `850` |
| Ціна | цілі гривні; об'єкт `price` (`from`, `to`, `is_free`, `currency`) | `{ "from": 150, "to": 400, "is_free": false, "currency": "UAH" }` |
| Короткий код | малі латинські літери, цифри, `_` | `invincibility_points` |
| Зображення | об'єкт `image`: `url`, `thumb_url`, `width`, `height`, `blurhash` | див. схему |
| Іконка | об'єкт `icon`: `key` і необов'язковий `url` | `{ "key": "shelter", "url": null }` |

Пояснення до окремих типів:

- **Час.** Сервер зберігає й віддає моменти часу в UTC. Там, де користувачу треба показати час «як у місті» (графік світла, графік роботи), сервер додатково віддає готові рядки `ГГ:ХВ`, тому додатку не потрібна база часових поясів.
- **Зображення.** У списках додаток показує `thumb_url`, на сторінці — `url`. Поки картинка вантажиться, показується розмита заглушка з `blurhash` (якщо він є).
- **Іконка.** Якщо додаток знає `key`, він показує вбудовану іконку. Якщо не знає і є `url`, вантажить картинку. Інакше показує стандартну іконку. Так нова категорія з'являється без оновлення додатку.
- **Позначка (`badge`) й характеристика (`attribute`).** Сервер віддає і код, і готовий підпис. Додаток може намалювати власну іконку для відомого коду, але підпис бере із сервера.

## 4. Місто

1. Кожен запит до даних міста має параметр `p_city_id`.
2. Ідентифікатор Чернігова сталий і записаний у контракті: `7c1f0c5e-6a54-4c0f-9a59-1d6f3a2b0001`. Додаток зберігає його як місто за замовчуванням, тому перший показ головної не чекає на `get_app_config`.
3. Якщо міста з таким ідентифікатором немає, функція повертає помилку `city_not_found`.

## 5. Гість

1. У MVP входу немає. Сервер розрізняє пристрої за **ідентифікатором встановлення** `installation_id`: це випадковий UUID, який додаток створює під час першого запуску і зберігає на пристрої.
2. Ідентифікатор передається лише у функції запису (`register_device`, `submit_report`, `track_events`) параметром `p_installation_id`. Функції читання його не приймають.
3. Ідентифікатор не є секретом і не дає жодних прав. Сервер використовує його для обмеження частоти запитів і для прив'язки налаштувань сповіщень.
4. Після перевстановлення додатку ідентифікатор новий. З версії `0.2.0` пристрій прив'язується до акаунта функцією `link_device` (`051-account`).

## 6. Списки

1. Параметри: `p_limit` (за замовчуванням 20, найбільше 50) і `p_cursor`.
2. Відповідь: `items` і `next_cursor`. Якщо `next_cursor` дорівнює `null`, це остання сторінка.
3. `p_cursor` — непрозорий рядок із попередньої відповіді. Додаток його не розбирає і не зберігає довше за сесію перегляду списку.

## 7. Помилки

Відповідь із помилкою має код HTTP і тіло за схемою `error`. Додаток дивиться лише на код HTTP і поле `message`.

| `message` | HTTP | Коли | Що робить додаток |
|---|---|---|---|
| `invalid_argument` | 400 | Параметр відсутній або має недопустиме значення | Помилка розробки; показує загальний стан «помилка» |
| `not_found` | 404 | Об'єкта немає або його знято з публікації | Екран «Цього вже немає», прибирає запис із кешу |
| `city_not_found` | 404 | Невідоме місто | Повертається до міста за замовчуванням |
| `rate_limited` | 429 | Забагато запитів | Повторює пізніше, користувачу показує кеш |
| `update_required` | 426 | Версія додатку нижча за підтримувану | Екран «Оновіть додаток» |
| `internal` | 500 | Збій на сервері | Показує кеш і стан «помилка» |
| `unauthenticated` | 401 | Функція потребує входу, а токена немає або він прострочений (з версії `0.2.0`, `051-account`) | Переходить у гостьовий режим і пропонує ввійти |
| `forbidden` | 403 | Дія недоступна цьому користувачу: наприклад, участь у програмі лояльності без підтвердженого номера (з версії `0.5.0`) | Показує пояснення й шлях до виправлення; запит не повторює |
| `conflict` | 409 | Дію неможливо виконати в поточному стані: бракує балів, тираж вичерпано, строк минув (з версії `0.5.0`); `details` містить пояснення для користувача | Показує `details` і оновлює екран |

Поле `details` містить пояснення для розробника чи користувача, `code` — службовий код бази; покладатись на них не можна. Приклад: `fixtures/001-conventions/error.rate_limited.json`.

Мережева помилка без відповіді сервера обробляється так само, як `internal`.

## 8. Кеш і свіжість

1. Додаток зберігає останню успішну відповідь кожного запиту на пристрої.
2. Під час відкриття екрана кеш показується одразу, запит іде у фоні, після відповіді екран оновлюється. Поруч із даними з кешу є час їх оновлення.
3. Кожен контракт у розділі «Оновлення» вказує, як часто додаток повторює запит.
4. Тривога має власні, суворіші правила свіжості (`010`).
5. Великі довідники (каталог, шари карти) мають номер версії. Додаток передає відому йому версію в `p_known_version`; якщо вона не змінилась, сервер відповідає `"not_modified": true` без даних.

## 9. Посилання всередині додатку

Плитки головної, push-сповіщення й інші елементи описують перехід рядком `moyemisto://…`.

| Посилання | Куди веде |
|---|---|
| `moyemisto://home` | Головна |
| `moyemisto://alert` | Карта з найближчими укриттями |
| `moyemisto://power` | Екран графіка світла |
| `moyemisto://entertainment/events` | Вкладка «Розваги», розділ «Події» |
| `moyemisto://entertainment/places` | Вкладка «Розваги», розділ «Місця» |
| `moyemisto://section/<код розділу>` | Екран розділу каталогу, наприклад `services` |
| `moyemisto://category/<код категорії>` | Список категорії, наприклад `food` |
| `moyemisto://event/<id>` | Сторінка події |
| `moyemisto://place/<id>` | Сторінка місця |
| `moyemisto://map?layers=<код>,<код>` | Вкладка «Карта» з увімкненими шарами |
| `moyemisto://map?place=<id>` | Вкладка «Карта» з центром на місці й відкритою нижньою карткою (правила — `030-map`) |

Нові посилання додаються лише в цей перелік (зміна MINOR).

Заплановані посилання наступних версій (додаються в таблицю під час встановлення відповідного тегу): `moyemisto://family/<id>` (`0.3.0`, `069-families`); `moyemisto://loyalty` і `moyemisto://loyalty/qr` (`0.5.0`, `081-loyalty`, `085-qr`).

## 10. Функція `get_app_config`

Налаштування додатку. Викликається під час кожного запуску у фоні; головна на неї не чекає.

**Параметри**

| Параметр | Тип | Обов'язковий | Опис |
|---|---|---|---|
| `p_platform` | `ios` або `android` | так | Платформа пристрою |
| `p_app_version` | рядок `X.Y.Z` | так | Версія додатку |

**Відповідь** (`$defs/get_app_config`)

| Поле | Опис |
|---|---|
| `contract_version` | Версія контракту, яку реалізує сервер |
| `server_time` | Поточний час сервера |
| `app.min_supported_version` | Найстаріша версія додатку, з якою сервер ще працює |
| `app.latest_version` | Остання версія в магазині |
| `app.update_required` | `true`, якщо `p_app_version` нижча за підтримувану; додаток показує екран оновлення |
| `app.store_url` | Сторінка додатку в магазині для цієї платформи |
| `default_city_id` | Місто за замовчуванням |
| `cities[]` | Міста: `id`, `slug`, `name`, `timezone`, `center`, `bounds`, `default_community`, `enabled_tabs` |
| `cities[].enabled_tabs` | Які вкладки футера показувати. У MVP без `civic`: вкладка «Громада» вмикається звідси у фазі 4 |
| `contacts` | Пошта підтримки, сторінка підтримки, сторінка «Стати партнером» |
| `legal` | Політика конфіденційності, умови користування, текст примітки про неофіційність оповіщення |

**Оновлення:** під час запуску й не частіше ніж раз на 6 годин.
**Приклад:** `fixtures/001-conventions/get_app_config.default.json`.

## 11. Версії контракту

Правила версій описано у `WORKFLOW.md`, розділ 4. Коротко: додавання поля, функції чи значення переліку — MINOR; зміна або видалення наявного — MAJOR і лише за згодою мобільного розробника. Кожна спека сервера й додатку вказує у `plan.md` версію контракту, на яку вона розрахована.

## 12. На що звернути увагу

- **Коди HTTP для помилок.** Контракт вимагає певний код HTTP і значення `message`. Як саме сервер цього досягає, вирішує спека `101-foundation`; це треба перевірити на справжньому проєкті Supabase до того, як на формат покладуться інші спеки.
- **Обмеження частоти.** Ідентифікатор встановлення легко підробити, тому обмеження мають враховувати ще й адресу, з якої прийшов запит. Конкретні межі задає сервер; додаток лише коректно обробляє `rate_limited`.
